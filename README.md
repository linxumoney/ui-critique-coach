# UI Critique Coach：AI UI/UX 评审与可访问性检查 Skill

好的 UI 评审不是换一种渐变、把圆角调大，也不是凭审美给分。它要回答：用户能不能看懂下一步、关键状态有没有覆盖、手机上会不会崩、键盘和读屏用户能不能完成任务。

`ui-critique-coach` 是一个面向设计师、前端和产品团队的开源 AI UI/UX 评审 Agent Skill。它从截图、设计稿或代码中检查用户任务、信息层级、交互状态、响应式布局和无障碍问题，并输出按 P0-P3 严重度排序的修改建议。兼容 Codex、Claude Code、Cursor 和 OpenCode。

## 使用示例

```text
用 $ui-critique-coach 评审这个页面截图和对应代码。
用户的核心任务是完成退款申请，请先找阻断问题，再谈视觉优化。
```

## 默认输出

- 核心任务完成度
- P0-P3 问题清单
- 每个问题的证据、影响和建议
- 缺失状态与移动端风险
- 最值得先改的三件事

## 安装

```bash
cp -R skills/ui-critique-coach ~/.codex/skills/
```

## 适用场景

- 网页、App、SaaS 后台和表单的 UI/UX 评审
- 根据截图找出信息层级和核心任务阻断
- 检查加载、空状态、错误、成功和权限状态
- 移动端响应式、长文本、缩放和内容溢出检查
- 键盘操作、焦点、标签、颜色对比和可访问性审查

## 常见问题

### 只有截图，没有代码能评审吗？

可以评审可见的信息层级、文案、状态和布局，但看不到的交互会标记为待验证，不会假装完成了完整流程测试。

### 它会重新设计整个页面吗？

默认先给按严重度排序的问题和修改建议。用户明确要求实现时，再结合现有设计系统修改代码。

### 会不会所有页面都改成同一种风格？

不会。Skill 优先遵循项目已有品牌和组件系统，并把个人审美与可用性事实分开。
